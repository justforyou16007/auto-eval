# Experiment Integrity

_Adapted from ARIS patterns for the eval-wiki context._

## Prevention of Fake Pass/Results

The eval-wiki pipeline enforces experiment integrity through multiple
layers of verification.

## Integrity Layers

### Layer 1: Output Capture

All agent output is captured directly from stdout/stderr, not from the
agent's own summary. This prevents the agent from self-reporting a pass.

### Layer 2: Noise Filtering

`capture-filter.py` filters out runtime noise before it can be persisted
as valid results. This prevents environment failures from being recorded
as evaluation passes.

### Layer 3: Evidence Verification

`evidence-check.py` verifies that all evidence files exist and are non-empty
before they can be referenced in a run record. This prevents empty or
missing evidence from being used to support a pass verdict.

### Layer 4: Provenance Validation

`provenance.py` validates that all provenance paths in run records resolve
to actual files. This prevents broken links from being used as evidence.

### Layer 5: Cross-Model Verification

ACQUIT roles must use a different model family than DRIVE roles. This
prevents the same model from generating and evaluating its own output.

### Layer 6: Self-Acquit Guard

The `run-state.py` accept command rejects reviewer names containing "claude"
to prevent self-acquitting.

### Layer 7: Convergence Detection

`iteration-log.py` tracks whether feedback loops are converging (issues
decreasing over time). Diverging feedback may indicate integrity issues.

## Forbidden Practices

1. **Hardcoding expected output**: Task output must be generated by the
   agent, not hardcoded in the test
2. **Self-reporting**: Agents must not report their own verdict
3. **Empty evidence**: Run records must have non-empty evidence files
4. **Circular provenance**: Evidence paths must not reference the run
   record itself
5. **Same-model ACQUIT**: ACQUIT evaluations must use a different model
   family than the generating model
